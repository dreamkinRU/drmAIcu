**Версия 3.11.1 Model** · Обновлено: 26.11.2026 · Единый источник версии — `version.py` · PR #10–#25 и патчи 144–162

## Компоненты
- **main.py**: UI-слой на NiceGUI/FastAPI (порт 8080): REST API, SSE-стриминг задач, опрос провайдеров, мониторинг RAM/VRAM, аналитик проекта, логи, рестарт. Движок патчей вынесен в отдельный модуль.
- **patch_engine.py**: Чистое ядро движка патчей (без NiceGUI): `safe_path`, two-phase атомарные транзакции, `TX_LOCK`, `expected_sha`, манифест, бэкапы. Его импортируют и тесты, и UI.
- **agent_engine.py (v2.3+)**: Асинхронный движок ИИ с поддержкой `run_task` и потокового `stream_task` для локальных (Ollama, Strata, LM Studio, Bionic) и облачных (Groq, OpenRouter, Together, Hugging Face, Gemini) провайдеров.
- **src/App.tsx (v.3.10.0 Model)**: React-панель управления (порт 5173), работающая через Vite Proxy.
- **core/plugins/**: Plugin System v1.0 — PluginManager (registry/loader/lifecycle/permissions/settings/secrets/events/confirmations), REST `/api/plugins/*` (`routes.py`), контракт `docs/PLUGIN_API_CONTRACT.md`. Repos Plugin — `plugins/repos/` (работа с локальными и сетевыми git-репозиториями: status/log/branches/diff/read_file — auto READ; add/commit/pull/push/fetch/checkout/sync — WRITE с подтверждением; Sync = полная замена `sync.bat`; авторизация как в локальном git, allowlist Git CLI). Данные плагинов — `data/plugins/` (в .gitignore).
- **Анти-джиттер UI (v.3.10.0)**: периодические опросы переведены на `POLL_INTERVALS` (плагины 15 с, логи 10 с, Ollama 15 с, модели 30 с, патчи 15 с, ресурсы 10 с) с проверкой изменения данных перед `setstate` — страница больше не перерисовывается без реальных изменений; удалён секундный таймер часов в App.tsx, перерисовывавший всё дерево приложения; ошибки вкладки «Репозитории» стали липкими (sessionStorage, снимаются вручную). Главная причина полных перезагрузок страницы устранена: Vite-dev следил за всем проектом — служебные записи бэкенда (журнал активности плагинов `data/plugins/activity/*.jsonl` пишется при каждом exec capability, settings.json, agents.json, pipelines.json, patch/, backups/) вызывали full reload; в vite.config.js добавлен `server.watch.ignored`. Ошибка открытия репозитория теперь показывает реальный git-stderr вместо заготовки.
- **Документация (v.3.10.0)**: вся документация собрана в `docs/` (ARCHITECTURE, USER_GUIDE, NEW_FEATURES, CHANGELOG, PLUGIN_SYSTEM, PLUGIN_API_CONTRACT), в корне — только README.md; вкладка «Плагины» получила кнопку «Описание системы плагинов» (рендер `docs/PLUGIN_SYSTEM.md` через `GET /api/md/docs/...`).

## Поток данных
- **Задачи ИИ и стриминг**: React (`useConsole.ts`) → Vite Proxy (`/api/task/stream` или `/api/task`) → FastAPI → `agent_engine.py` → локальные/облачные LLM API (SSE chunks + метрики `tok/s`, `TTFT`).
- **Провайдеры и модели**: React (`ProvidersTab.tsx`) → `POST /api/providers/ping` (параллельная проверка доступности через `ThreadPoolExecutor` каждые 5с) и `POST /api/providers/config` (сохранение URL, портов и ключей в `config.json`), а также `GET /api/{ollama|strata|lmstudio|bionic}/models` с фильтрацией `embed`-моделей.
- **Патчинг**: React (`usePatches.ts` сканирует `patch/` и `Загрузки`) → `POST /api/patches/apply` → `TX_LOCK` → per-file сверка SHA с диском → `resolve()` → Фаза 1: Валидация всех `operations` (включая `expected_sha`) → Фаза 2: Бэкап → Запись `.tmp` → `os.replace` → Проверка побайтового SHA-256 → Обновление `patch_manifest.json` → автоархивация и тихий рестарт при изменении `.py`.
- **Мониторинг ресурсов**: React (`Footer.tsx`) → `GET /api/system/resources` (опрос каждые 10с при реальном изменении метрик через `ctypes` / PowerShell) → отрисовка шкал заполнения `RAM` и `VRAM`.
- **Очистка**: React → `POST /api/project/scan` → FastAPI обход дерева файлов → MD5-хеширование → Эвристический анализ `get_cleanup_recommendation` → Возврат структурированного JSON с бейджами.
- **Перезапуск**: Кнопка в подвале или автотриггер после `.py`-патча → `POST /api/system/restart` → Создание `restart.flag` → Остановка процессов → `launcher.bat` видит флаг и перезапускает без открытия нового окна браузера.
- **Логи**: `/api/logs` возвращает последние 100 записей из глобального `LOG`.
- **Документация**: `/api/md/{name}` читает/пишет MD-файлы.
- **Статус**: `/api/status` возвращает состояние системы и готовность ядра.
- **Валидация**: `validate()` проверяет `.py` через `ast.parse` и `.json` через `json.loads`.
- **Валидация TSX**: `check_ts()` вызывает локальный `typescript` через `tscheck.cjs` для проверки синтаксиса до записи.
- **Песочница путей**: `safe_path()` отклоняет `../` и абсолютные пути в операциях и файловых эндпоинтах.
- **Байтовый SHA**: `sha_file()` вычисляет SHA-256 файла по байтам для детекта изменений и `expected_sha`.

## Механизмы безопасности и надёжности
- **Universal AI-Guardian**: Валидация `ast.parse` для Python, `json.loads` для JSON и `typescript` для TSX перед любой записью.
- **Двухфазный атомарный коммит**: Гарантия «всё или ничего» при мультифайловых патчах. Фаза 1 валидирует все файлы до записи; Фаза 2 пишет и проверяет контрольные суммы.
- **Замок транзакций** (`TX_LOCK`): одна транзакция одновременно, защита от двойного клика (B12, B24).
- **Детект устаревшего кода** (per-file SHA): `expected_sha` в операции + повторная сверка SHA-256 каждого целевого файла с диском между расчётом и записью; если файл изменён вне панели — весь патч отказывается с ошибкой «Код на диске изменился вне панели (stale target_file)» (B19, B21).
- **Накопление операций** (кэш в `compute_ops`): Последовательные операции над одним файлом складываются корректно, а не перезаписывают друг друга (B18).
- **Дедупликация записей**: В `apply_patch` операции дедуплицируются по файлу перед фазой записи.
- **Идемпотентность `search_and_replace`**: Если замена уже применена, операция возвращает содержимое без изменений (B17).
- **1 бэкап + ротация 10**: Вместо тройного бэкапа (`_verified.bak` + `_LATEST.bak`). Имена по относительному пути с микросекундами (`src__App.tsx_<ts>.bak`) (B6, B16).
- **Автооткат**: При несовпадении контрольной суммы после записи система восстанавливает файлы из бэкапов. `written.append()` до проверки суммы гарантирует откат сбойного файла (B7).
- **Песочница путей**: `safe_path()` отклоняет `../` и абсолютные пути (B9).
- **Байтовый SHA-256**: Контрольная сумма считается по байтам, файлы сохраняются с исходным типом переносов строк (B11).
- **Ротация манифеста**: Последние 100 записей `applied` / 500 записей `history` (B14).
- **88 тестов**: `python -m pytest tests` покрывает все критические дефекты движка (B1–B44), включая security-регрессы (path traversal, tampered-бэкап, дубликаты `patch_id`, мусорные diff).

## Известные ограничения и долги
- **CORS/host**: Закрыто в 3.5.3 — только localhost, `127.0.0.1`.
- **`expected_sha` поддерживается движком, но не генерируется в UI**: Поле можно задать вручную в операции, но панель его автоматически не передаёт.
- **Документация**: актуализирована в `v.3.9.0 Model` (26.11.2026) — отражены новые провайдеры, объединённая вкладка «Провайдеры», SSE-стриминг и обновлённый UI.
- **Декомпозиция `main.py`**: Движок патчей вынесен в `patch_engine.py` (3.5.3); `App.tsx` остаётся основным контейнером состояния.
- **CI**: Добавлен в `.github/workflows/ci.yml` (`pytest` + `tsc` + `vite build`).
- **`sync.bat`**: отчёт о последнем merged PR требует установленного `gh` CLI — есть fallback на `git log` (PR #17, #19).
