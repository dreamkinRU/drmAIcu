# HANDOFF — передача работы над drmAIcu (для нового исполнителя)

**Актуально для:** v.3.14.0 Model · 27.11.2026 · PR #10–#53 смержены · PR #54 — текущая ветка hardening · этот документ — точка входа нового исполнителя (человека или AI-ассистента).

---

## 1. Что это за проект

- drmAIcu — локальная панель «Universal AI-Guardian»: FastAPI (через NiceGUI `app`) + PATCHMASTER (`patch_engine.py`, crash-recoverable multi-file транзакции; не atomic visibility для внешних читателей) + AI-движок (`agent_engine.py`) на бэкенде; React 18 + Vite + Tailwind 4 на фронтенде (`src/`).
- Система плагинов v1.0 (`core/plugins/`) + встроенный плагин Репозитории (`plugins/repos/`): работа с локальными git-репозиториями (status/diff/commit/push/pull --rebase/sync/rebase-recovery) через Capability Gateway с подтверждениями.
- Заказчик работает на Windows, проект лежит в облачной папке `G:\Mega\git\drmAIcu` — это источник половины специфических багов (см. §7).

## 2. Как запустить и проверить

- Полный запуск: `launcher.bat` (watchdog: Python Core на :8080 + Vite dev на :5173 + браузер). Только бэкенд: `python main.py`.
- Тесты бэкенда: `python -m pytest tests -q`; фактический результат фиксируется в GitHub Actions конкретного коммита, историческое число тестов в HANDOFF не хардкодится.
- Фронтенд: `npx tsc --noEmit` (typecheck), `npm run build` (сборка). CI гоняет pytest на ubuntu-latest **и** windows-latest + typecheck/build — см. `.github/workflows/ci.yml`.
- Версия в шапке UI приходит из `GET /api/version` (значение `version.py`); после обновления у заказчика **обязателен** `npm run build`, иначе он видит старую сборку.

## 3. Замороженные правила (НЕ НАРУШАТЬ)

- **PATCHMASTER — единственный путь применения AI-правок исходников.** Плагин Репозитории не имеет права писать исходники или вызывать `apply_patch` (это покрыто контрактными тестами). Не «упрощайте» это.
- **Политика Plugin System v1.0 заморожена:** READ-операции — автоматически; WRITE (push/commit/pull/sync) — подтверждение на каждое действие; CRITICAL — отдельное подтверждение; автономного режима НЕТ; минимальную политику плагин ослаблять не может. Single-use токены подтверждений (TTL 15 мин, привязка к params-hash).
- Git CLI — **только** через `plugins/repos/git_service.py` (allowlist `GIT_COMMANDS`, args списком, `shell=False`, таймауты). Никаких shell-строк.
- Ошибки — всегда видимые, персистентные (не исчезающие плашки), с текстом «Путь исправления: …». Плашка, исчезающая через полсекунды — считайте багом.
- «Не придумывай ничего. Не пытайся обмануть. Только реальный рабочий код!» — никаких заглушек, выданных за готовое. Проверено = запущено локально (pytest/tsc/build/e2e), а не «должно работать».
- Документация обновляется **каждый коммит** (см. §4). В корне — только README.md, остальная документация в `docs/`.

## 4. Версионирование — чек-лист на каждый релиз (заказчик требует неукоснительно)

1. `version.py` — единственный источник (`VERSION = 'x.y.z'`); `package.json` синхронно.
2. UI-шапка берёт версию из `/api/version` → проп `version` в `Header.tsx`; хардкоды вида `v.3.6.1` в коде запрещены (контракт-тест следит).
3. Строка 3 заголовков README.md / docs/USER_GUIDE.md / docs/ARCHITECTURE.md: `**Версия X.Y.Z Model** · Обновлено: ДД.ММ.ГГГГ · … · PR #10–#NN и патчи 144–162` (расширять диапазон PR по факту мержа).
4. `docs/CHANGELOG.md` — новая секция сверху: `## vX.Y.Z Model (Текущая) — ДД.ММ.ГГГГ`, у предыдущей снять пометку «(Текущая)». **Файл CRLF** — править только скриптом с `newline=''`, иначе получите +600/-600 дифф.
5. Патч-версия для мелких фиксов, минор — для фич. Бампать в том же PR, что и изменения.

## 7. Грабли (грабят больно, читайте до старта)

- **Mega/облако держит файлы** ([WinError 5]): заказчик 2 раза ловил смерть плагина из-за этого. Уже сделано: retry ~16с, деградация в памяти + баннер, fail-fast при разноверсионных файлах. Заказчику советовать: пауза синхронизации на время обновлений, `data/` в исключения облака, после каждого обновления — `npm run build` и перезапуск.
- **Частичный git pull** в облачной папке оставляет разноверсионные файлы (симптом: `capability_failed ... has no attribute ...`). Лечение: пауза облака → git pull → удалить `__pycache__` в `plugins/repos` и `core/plugins` → рестарт.
- `docs/CHANGELOG.md` — **CRLF**, править только python-скриптом с `newline=''`.
- Тест `tests/test_docs_hygiene.py` запрещает ручные переносы строк внутри абзацев документации — пишите абзацы/буллеты **одной длинной строкой**.
- Инструменты правки файлов могут падать на кириллице — используйте python-хередоки: `io.open(path, encoding='utf-8', newline='')` → replace → write.
- У заказчика однажды потребовалось `git config --global --add safe.directory G:/Mega/git` — упомянуто в docs; вспоминайте при ошибках «dubious ownership».
- UX-паттерн против «прыгающих» элементов: обновлять состояние только при реальном изменении (`setState(prev => sameJson(prev, next) ? prev : next)`) — применяется в хуках Footer/usePatches/usePlugins.
- Тест-паттерны: реальные git-репо через subprocess (`make_repo`), bare-remote для sync-флоу, `build_manager` (атрибут `base`), `grant_all` в test_repos_last_sync.py, monkeypatch для инъекций отказов, UI-контракты проверяют кириллические строки в .tsx.
- Ветка/PR: `vibe/<slug>-9018bf`, PR с title+body через файлы (heredoc), push ветки ДО создания PR; **main не пушим никогда, force — никогда**; заказчик мержит сам. НИКОГДА не пушить в ветку, не проверив, что её PR ещё открыт (однажды коммиты улетели в уже смерженный PR и потерялись — заказчик это воспринял как обман).
- После создания PR: сразу сообщить URL, предложить мониторинг CI, при падении — чинить в том же PR.

## 8. Стиль работы с заказчиком

- Общение на русском. Ошибки признавать сразу и прямо, без защитной позы (после каждого инцидента — что случилось, почему не поймали тесты, что изменено).
- Не обещать непроверенного. Каждый факт «готово» подкреплён выводом команды (pytest/tsc/build/e2e).
- Не задавать лишних вопросов — сначала прочитать этот файл, docs/, git log; спрашивать только при реальной развилке (2–4 конкретных варианта).
- Уведомления в UI — честные: что отправлено, что получено, текущий HEAD; «всё прошло» без деталей — считается обманом.
