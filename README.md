## Описание

Универсальный AI-Guardian с поддержкой локальных и облачных LLM-провайдеров, SSE-стримингом в консоли и движком журналируемых crash-recoverable патчей.

## Возможности

### 🤖 AI-движок и провайдеры (v.3.10.0 Model)
- ✅ **9 провайдеров**: локальные **Ollama**, **Strata** (`127.0.0.1:47831/v1`), **LM Studio** (`localhost:1234/v1`), **Bionic AI** (`localhost:1235/v1`) и облачные **Groq**, **OpenRouter**, **Together AI**, **Hugging Face**, **Gemini**
- ✅ **Единая вкладка «Провайдеры» (Master–Detail)**: живой опрос статусов каждые 5 секунд, тумблеры вкл/выкл, настройка хоста/порта/API-ключа и выбор активной модели в одном окне
- ✅ **Автоподгрузка и фильтрация моделей**: автоматическое скрытие `embed`-моделей из списков локальных серверов
- ✅ **Потоковая консоль (SSE)**: стриминг ответов в реальном времени с телеметрией (`tok/s`, `TTFT`, токены), остановкой (`AbortController`), повтором запроса и отправкой по `Enter`
- ✅ **Fast / Judge режимы**: быстрая генерация или мульти-модельный выбор с судьёй и автоматическим retry

### 🔒 Безопасность и надёжность движка патчей
- ✅ **Crash-recoverable multi-file transaction**: журнал до первой записи и восстановление после аварии; внешним читателям не обещается атомарная видимость набора файлов
- ✅ **Замок транзакций**: `TX_LOCK` сериализует `apply`/`rollback` — одна транзакция одновременно
- ✅ **Детект устаревшего кода**: сверка с базовым SHA перед записью (`expected_sha` в операции + re-check диска между расчётом и записью); патч целиком отказывается применяться, если код на диске изменился вне панели
- ✅ **Неоднозначность запрещена**: `search_and_replace` падает, если подстрока входит в файл несколько раз (вместо тихой замены первого вхождения); неподходящий `find` даёт явную ошибку, а не тихий no-op
- ✅ **Накопление операций**: 20 операций над одним файлом складываются корректно, а не перезаписывают друг друга (B18)
- ✅ **Ротация манифеста**: последние 100 applied / 500 history
- ✅ **1 бэкап + ротация 10**: один timestamp-бэкап + `_LATEST.bak` на операцию, старые бэкапы автоматически удаляются ротацией (максимум 10 на файл); в манифесте — относительные пути от корня проекта
- ✅ **Fail-closed TS/JS validation**: PASS / FAIL / UNAVAILABLE; отсутствие Node.js, валидатора или timeout больше не маскируются под успешную проверку
- ✅ **Байтовый SHA-256**: контроль целостности с сохранением CRLF/LF (B11)
- ✅ **Песочница путей**: `../` и абсолютные пути отклоняются (B9)
- ✅ **300+ тестов**: покрывают все критические дефекты движка (B1–B44), включая security-регрессы (path traversal, tampered-манифест, tampered-бэкап, дубликаты патчей)

- ✅ **Регрессионные тесты hardening**: повреждённый crash-журнал, недоступный TypeScript validator, browser-origin guard, Resource Governor и redaction Git credentials; актуальный итог — в GitHub Actions CI

### 🛠️ Управление проектом и мониторинг
- ✅ **Мониторинг RAM / VRAM в подвале**: визуальные шкалы заполнения памяти в реальном времени и кнопка перезапуска панели
- ✅ **Автообнаружение патчей**: сканирование `patch/` и папки `Загрузки`, модальное окно применения, автоархивация и тихий рестарт при `.py`-патчах
- ✅ **Умный анализатор файлов**: поиск дубликатов по MD5, мусора, устаревших версий (`_v3`, `_fixed`, `_ru`) с откатом через `project_archive/`

## Установка

```bash
git clone [https://github.com/dreamkinRU/drmAIcu.git](https://github.com/dreamkinRU/drmAIcu.git)
cd drmAIcu
pip install -r requirements.txt
npm install
```

## Запуск

```bash
launcher.bat
```

Откройте http://127.0.0.1:5173 в браузере.

## Тестирование движка патчей

```bash
python -m pytest tests -v
```

Ожидаемо: **335 passed, 1 skipped** (регресс-тесты покрывают дефекты B1–B44).

Полный backend suite запускается на Ubuntu и Windows через GitHub Actions; frontend typecheck/build — на Ubuntu. Результаты конкретного PR смотрите во вкладке Checks.
