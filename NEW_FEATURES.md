# Новые возможности drmAIcu v3.5.0

## 1. Мультифайловые атомарные патчи (MULTI-ATOMIC)
Раньше один патч мог изменить только один файл. Теперь система поддерживает массив `operations`.
**Главное преимущество: Двухфазный коммит.**
- **Фаза 1 (Валидация)**: Система вычисляет новое состояние для всех файлов из списка и проверяет их синтаксис. Если хоть один файл невалиден, процесс останавливается, диск не трогается.
- **Фаза 2 (Запись)**: Создаются бэкапы всех целевых файлов. Файлы записываются. Проверяется SHA-256 каждого файла. Если контрольная сумма не совпадает, система **автоматически восстанавливает все файлы из бэкапов**. Гарантируется состояние "всё или ничего".

## 2. Железобетонный движок unified_diff
Старый движок полагался на номера строк (`@@ -200`), что приводило к вставке кода не туда при малейшем сдвиге.
**Новый движок:**
- Ищет точное совпадение текстового контекста удаляемых строк.
- Если контекст встречается в файле несколько раз, патч **отклоняется** с ошибкой "Неоднозначный контекст", предотвращая порчу файла.
- Поддерживает fuzzy-допуск (игнорирование хвостовых пробелов).
- Идемпотентен: повторное применение уже применённого патча безопасно пропускается.

## 3. Умный анализатор очистки проекта
Вкладка "Проект" теперь не просто показывает статистику, а анализирует каждый файл:
- Находит пустые файлы и системный мусор (`.DS_Store`, `Thumbs.db`).
- Обнаруживает устаревшие версии по суффиксам (`_v3.0.4`, `_fixed`, `_ru`, `_backup`) во всех папках проекта.
- Находит дубликаты по MD5-хешу и предлагает удалить копии, оставив оригинал.
- Все удаления происходят через безопасное перемещение в `project_archive/` с датой.

## 4. Перезапуск системы из UI
Добавлена кнопка в шапку панели. Она отправляет запрос на бэкенд, который:
1. Создаёт флаг `restart.flag`.
2. Корректно убивает процессы Python и Node.js по заголовкам окон.
3. Завершает работу.
4. `launcher.bat` (watchdog) видит флаг или падение процесса и автоматически перезапускает систему с чистого листа.

## 5. Операция `search_and_replace` с нормализацией переносов строк
Для точечных изменений добавлен новый тип операции, который решает главную проблему кроссплатформенной разработки — несовпадение переносов строк (`\r\n` vs `\n`).
**Как это работает:**
- При поиске движок временно приводит и содержимое файла, и искомую строку (`find`) к единому формату (Unix LF).
- После успешной замены файл сохраняется с исходным типом переносов строк (например, Windows CRLF).
- **Когда использовать**: Для замены конкретных классов, коротких строк кода или исправления опечаток, где создание полноценного `unified_diff` избыточно и подвержено ошибкам из-за пробелов.
